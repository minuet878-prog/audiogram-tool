# Decisions

## 2026-10-08 v1

**分類規則（我定的臨床規則）**
- PTA 用四頻：500、1000、2000、4000 Hz。不先四捨五入，直接拿平均值比門檻。
- 程度六級：≤25 正常、≤40 輕度、≤55 中度、≤70 中重度、≤90 重度、>90 極重度。
  原本想用七級（≤15 正常、16–25 極輕度），後來改成 25 以內都算正常，這樣程度和類型共用同一條界線。
- 類型：氣導 ≤25 → 正常；氣骨導差 <15 → 感音神經性；差 ≥15 且骨導 ≤25 → 傳導性；差 ≥15 且骨導 >25 → 混合性。
  第一版規則是「看氣導、骨導、差距三個條件的組合」，結果漏了「氣導異常、骨導正常、沒差距」這一格。改成先看差距再看骨導就沒有空格。
- 氣骨導差用「氣導平均 − 骨導平均」，不是逐頻率比較。
- 氣導正常時不需要骨導也能下結論。

**技術**
- Flask 而不是單一 HTML＋JS：計算用 Python 寫，測試我看得懂，之後也能對照搬進 HearWell。
- 聽力圖用 SVG 在伺服器端畫，不用圖表套件：不依賴網路，座標算法可以測試。代價是沒有互動。
- 計算（`classify.py`）完全不碰 Flask，要搬走只帶這一個檔案。
- 有測的氣導點全部連線，中間缺頻率也跨過去（選項一）。

**踩到的坑**
- `int("1_0")` 是 10，`int("１０")` 也是 10。審查時才抓到，改成先用正規表示式限定「可有負號的 1–3 位數字」。
- 頁面說明文字原本用了排版用的負號「−」，照著複製貼上會被自己的檢查擋掉，改成一般減號。
- 直接打 `pytest` 找不到 `app` 模組，加了 `pytest.ini` 設定 `pythonpath = .`。

**流程觀察**
- 需求階段改了三次規則（類型規則的空格、25 的界線、六級），都發生在寫程式之前，沒有重工。
- 審查找到的都是輸入檢查和測試深度的問題，核心規則沒錯。

## 2026-10-08 v2 視覺優化

**決策**
- 版面選 A（桌機左右並排，手機上下排），結果卡依程度上色，正常範圍加淺綠底。三個選項都是看過比較頁才定的。
- 用 Bootstrap：最主流、文件多。只放 CSS，不放 JS。
- Bootstrap 下載一份放進專案，不用 CDN：沿用 v1「不依賴網路」的原則。官方原檔不改，升級時直接換檔。
- 表頭從「250 Hz」改成「250」，單位寫在說明文字裡。不這樣做的話，手機上表格會放不下。
- `parse()` 的錯誤改成 {欄位名稱: 訊息}，這樣才知道哪一格要標紅。檢查規則沒動。
- 舊測試依賴的標記（`section id`、`mark` class、`class="error"`）全部保留，不改舊測試去配合新畫面。

**踩到的坑**
- 想用 `<small>` 把「dB HL」縮小，結果舊測試找不到「45 dB HL」這串字。後來改回連在一起。
- 在 `<ul class="error">` 加了 Bootstrap 的 class，變成 `class="error mb-0"`。這會讓舊測試的「沒有錯誤」檢查永遠通過。改回原本寫法，間距改用 CSS 處理。
- 想用 `background-image: none` 去掉 Bootstrap 錯誤欄位的驚嘆號圖示，結果沒效。原因是 CSS 的優先權：Bootstrap 的 `.form-control.is-invalid` 比我的 `.thresholds input` 寫得更具體。改成寫得比它更具體的選擇器。
- Flask 沒開除錯模式時，會把模板留在記憶體裡重複使用，改了模板要重新啟動伺服器才看得到。重啟後先看程式的啟動時間，確認真的是新的再驗證。
- 圖例的 `<g class="right">` 跟右耳標記群組長得一樣，舊測試可能拿圖例來比對、變成永遠通過。審查時抓到，改成 `legend-item right`。
- 自動測試量不到手機上的實際寬度，要在瀏覽器裡用 390px 寬的 iframe（內嵌框架，網頁裡再開一個網頁）量。

**流程觀察**
- 自動測試抓不到的三個問題都是看截圖才發現的：手機表格放不下、驚嘆號圖示、伺服器沒重啟。畫面類的需求，瀏覽器驗收是必要的。
